title: Runtime vs Interface
description: Distinguish the long-running service wrapper from the transports that feed messages into it.

---

Runtime and interfaces are complementary, not competing, layers.

## Comparison

| Layer | Responsibility |
| --- | --- |
| `AgentServer` and `AgentRuntime` | serve the agent, mount routes, supervise interfaces, and run triggers |
| `Interface` | adapt one transport such as Telegram, Slack, Discord, WebSocket, WhatsApp, or email |

## Decision rule

- Use an interface when you need to speak one platform's protocol.
- Use the runtime when that interface must be mounted, supervised, or run together with HTTP routes and scheduling.

## Tested example

```python
from fastapi.testclient import TestClient

from definable.agent import Agent
from definable.agent.interface import WebSocketInterface
from definable.agent.runtime import AgentServer
from definable.agent.testing import MockModel

agent = Agent(model=MockModel(responses=["pong"]), instructions="Reply briefly.")
interface = WebSocketInterface(path="/agent/ws")
app = AgentServer(agent, interfaces=[interface]).create_app()
client = TestClient(app)
paths = {route.path for route in app.router.routes}

assert client.get("/health").status_code == 200
assert "/run" in paths
assert "/agent/ws" in paths
```

## Practical guidance

- Some interfaces, such as WebSocket or Call, require an HTTP server because they expose routes.
- Others, such as Telegram polling, can run inside a runtime without exposing public HTTP endpoints.
- When one deployment combines several interfaces, let `AgentRuntime` or `InterfaceGateway` supervise them together.
