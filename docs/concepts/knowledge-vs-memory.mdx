title: Knowledge vs Memory
description: Separate long-lived external facts from session-scoped conversational continuity.

---

Knowledge and memory both enrich a run, but they solve different problems.

## Comparison

| Layer | Stores | Queried by | Typical source |
| --- | --- | --- | --- |
| `Knowledge` | documents and chunks | semantic retrieval | files, URLs, notes, handbooks |
| `Memory` | prior messages and summaries | session lookup | previous conversations |

## Decision rule

- Use `Knowledge` when the agent needs facts that exist outside the current conversation.
- Use `Memory` when the agent needs to remember what this user or session already said.
- Use both when the agent needs external grounding and continuity.

## Tested example

```python
import asyncio

from definable.knowledge import Document, Knowledge
from definable.memory import InMemoryStore, Memory
from definable.model.message import Message

from examples.docs.support import MockVectorDB


async def main() -> None:
    knowledge = Knowledge(vector_db=MockVectorDB(), context_format="markdown")
    knowledge.add(Document(content="Refunds close after 30 days."), chunk=False)
    result = knowledge.search("refund", limit=1)[0]

    async with Memory(store=InMemoryStore()) as memory:
        await memory.add(Message(role="user", content="My plan is enterprise."), session_id="alice")
        alice_entries = await memory.get_entries("alice")
        bob_entries = await memory.get_entries("bob")

    assert result.content == "Refunds close after 30 days."
    assert len(alice_entries) == 1
    assert bob_entries == []


asyncio.run(main())
```

## Common mistake

Do not use memory as a document store. If a fact should be available to many users or many sessions, it belongs in knowledge, not in one conversation history.
