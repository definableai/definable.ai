The `definable.agent` package is the control plane for the framework. An `Agent` wraps a model with context building, tool execution, optional knowledge and memory, guardrails, runtime hooks, and observability.

## What an agent is

An agent is the right abstraction when one model-driven worker should decide how to use instructions, context, tools, and retrieved information to finish a task.

Use an agent when:

- one worker can own the task end to end
- tool calling should stay model-driven
- memory or retrieval should plug into the same run loop
- you want one consistent sync, async, and streaming API

## How an agent run works

An `Agent` wraps a model with a repeatable lifecycle:

1. Build the run context.
2. Recall optional layers such as knowledge, memory, or research.
3. Apply reasoning and guardrails.
4. Execute the tool loop until the run completes, pauses, or blocks.
5. Store artifacts and emit replay, tracing, and observability data.

## Tested example

```python
from definable.agent import Agent
from definable.agent.run import RunStatus
from definable.agent.testing import MockModel

agent = Agent(
    model=MockModel(responses=["12"]),
    instructions="Reply with the answer only.",
)

output = agent.run("What is 5 + 7?")

assert output.content == "12"
assert output.status == RunStatus.completed
```

## Start from the right surface

- Use [`Agent`](/reference/agents/agent) when you need a production agent with tools, memory, or knowledge.
- Use [`pipeline`](/agents/pipeline) when you are extending the execution model itself.
- Use [`runtime`](/agents/runtime) when you need HTTP endpoints, webhooks, interfaces, or scheduling around an agent.
