`definable.agent.eval` gives you a shared shape for agent evaluation. Every eval runs one or more `EvalCase` inputs against an agent or team and produces structured results you can use in CI, benchmarks, or regression checks.

## Public API

| Type | Purpose |
| --- | --- |
| `EvalCase` | One input, optional expected answer, and metadata |
| `EvalSuite` | Aggregate results for a batch of cases |
| `PerformanceEval` | Measure runtime and memory |
| `ReliabilityEval` | Check whether expected tools were called |
| `AccuracyEval` | Score actual output against expected output with a judge model |
| `AgentAsJudgeEval` | Use custom scoring criteria and judge prompts |

## Which eval to choose

- Use `PerformanceEval` when you want deterministic local checks.
- Use `ReliabilityEval` when tool choice matters as much as the final answer.
- Use `AccuracyEval` or `AgentAsJudgeEval` when semantic quality matters and you can afford a judge model.

## Tested example

```python
import asyncio

from definable.agent import Agent
from definable.agent.eval import EvalCase, PerformanceEval
from definable.agent.testing import MockModel

agent = Agent(model=MockModel(responses=["done", "done"]), instructions="Reply briefly.")
evaluation = PerformanceEval(runs=2, warmup_runs=0)

result = asyncio.run(evaluation.arun(agent, EvalCase(input="ping")))

assert result.success is True
assert result.runs == 2
assert len(result.durations) == 2
```

## Recommended workflow

1. Start with performance and reliability checks using `MockModel`.
2. Add judge-based evals once the run loop and tool behavior are stable.
3. Store `EvalSuite.to_dict()` output in CI artifacts so regressions are easy to inspect.
