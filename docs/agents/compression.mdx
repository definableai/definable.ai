`definable.agent.compression` is the safety valve for verbose tool output. It keeps the run loop usable when tools return long logs, HTML, or large result payloads by summarizing old tool messages before they dominate the prompt.

## Public API

| Type | Purpose |
| --- | --- |
| `Compression` | User-facing configuration attached to `Agent` |
| `CompressionManager` | Internal engine that decides when and how to compress |

## What gets compressed

Compression operates on tool-role messages. It can trigger when:

- the number of uncompressed tool results crosses a threshold,
- the prompt token count crosses a threshold, or
- one tool result is individually too large.

## Tested example

```python
from definable.agent.compression import Compression, CompressionManager
from definable.model.message import Message

config = Compression(tool_results_limit=2, single_result_size=500)
manager = CompressionManager(
    compress_tool_results_limit=config.tool_results_limit,
    compress_single_result_size=config.single_result_size,
)

messages = [
    Message(role="tool", content="first result", tool_name="search"),
    Message(role="tool", content="second result", tool_name="search"),
]

assert manager.should_compress(messages) is True
```

## Practical guidance

- Start with the count-based default. It is predictable and easy to reason about.
- Add a token limit when tools return highly variable payload sizes.
- Use a cheaper compression model than your main reasoning model when latency matters.
