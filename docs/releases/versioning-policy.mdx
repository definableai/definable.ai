This repository publishes a package version in `pyproject.toml`. Use that version as the compatibility boundary for docs, examples, and deployments.

## Practical policy

- Pin the package version in production.
- Read migration guidance before changing the pinned version.
- Re-run local docs-backed validation after any upgrade, even if the version bump looks small.

The docs do not assume that every change is operationally trivial. For production work, validate behavior instead of relying on version number intuition alone.

## Tested example

```python
from packaging.version import Version

current = Version("0.8.0")
next_patch = Version("0.8.1")
next_minor = Version("0.9.0")

assert next_patch > current
assert next_minor > next_patch
```
