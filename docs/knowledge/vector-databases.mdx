Vector databases sit under `Knowledge`. They store embedded documents and run similarity search over query embeddings.

## Built-in backends

| Backend | Import | Typical use |
| --- | --- | --- |
| `InMemoryVectorDB` | `definable.vectordb` | local development and tests |
| `PgVector` | `definable.vectordb` | PostgreSQL-based production storage |
| `Qdrant`, `ChromaDb`, `MongoDb`, `RedisDB`, `PineconeDb` | `definable.vectordb` | managed or specialized vector infrastructure |

## Tested example

```python
from definable.knowledge import Document
from definable.vectordb import InMemoryVectorDB

from examples.docs.support import MockEmbedder

embedder = MockEmbedder()
vector_db = InMemoryVectorDB(name="docs", embedder=embedder)

document = Document(content="Agents can call tools to interact with external systems.")
document.embed(embedder)

vector_db.insert("doc-1", [document])
results = vector_db.search("tools", limit=1)

assert vector_db.count() == 1
assert results[0].content == "Agents can call tools to interact with external systems."
```

## Guidance

- Start with `InMemoryVectorDB` while shaping the retrieval flow.
- Switch backends by replacing the `vector_db=` argument on `Knowledge`.
- Keep embedder and stored document vectors consistent. Query search quality depends on that pairing.
