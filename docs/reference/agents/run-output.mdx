---
title: RunOutput
description: Final execution object returned by agentic runs.
---

`RunOutput` is the common result object for agentic execution. Agent runs and several higher-level flows converge on this shape for final content, metadata, metrics, and user-control state.

## Key field groups

| Group | Fields |
| --- | --- |
| Identity | `run_id`, `agent_id`, `agent_name`, `session_id`, `parent_run_id`, `user_id` |
| Content | `content`, `parsed`, `content_type` |
| Reasoning | `reasoning_content`, `reasoning_steps`, `reasoning_messages` |
| Model metadata | `model`, `model_provider`, `model_provider_data`, `metrics` |
| Messages and tools | `messages`, `tools`, `additional_input` |
| Media and citations | `images`, `videos`, `audio`, `files`, `response_audio`, `citations`, `references` |
| Control state | `status`, `requirements`, `events`, `phase_metrics` |

## Status and helper properties

- `status` is a `RunStatus` enum such as `COMPLETED`, `PAUSED`, or `ERROR`.
- `is_paused` and `is_cancelled` are convenience properties.
- `active_requirements` exposes unresolved human-in-the-loop requirements.
- `tools_requiring_confirmation`, `tools_requiring_user_input`, and `tools_awaiting_external_execution` filter the tool execution list by behavior.

## Serialization

`RunOutput` can be serialized with `to_dict()` or `to_json()`. Those methods normalize nested metrics, messages, media, tool execution records, and status values into transport-friendly structures.

## Tested example

```python
from definable.agent.run import RunStatus
from definable.agent.run.agent import RunOutput
from definable.model.metrics import Metrics

output = RunOutput(
    content="done",
    status=RunStatus.completed,
    model="mock-model",
    metrics=Metrics(input_tokens=1, output_tokens=1, total_tokens=2),
)

payload = output.to_dict()

assert output.is_paused is False
assert payload["status"] == "COMPLETED"
assert payload["metrics"]["total_tokens"] == 2
assert payload["content"] == "done"
```
