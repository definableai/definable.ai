`Agent` is the primary execution object in Definable. It combines a model with optional capability layers such as memory, knowledge, thinking, tools, skills, interfaces, tracing, and runtime hooks.

## Constructor shape

The constructor is organized into a few logical groups:

| Group | Important fields |
| --- | --- |
| Identity | `name`, `session_id`, `instructions`, `config` |
| Model | `model` |
| Capability layers | `memory`, `knowledge`, `thinking`, `compression`, `context`, `deep_research` |
| Tooling | `tools`, `toolkits`, `skills`, `skill_registry` |
| Runtime and visibility | `interfaces`, `gateway`, `tracing`, `debug`, `observability` |
| Operational add-ons | `security`, `usage`, `readers`, `guardrails` |

The critical design rule is that major layers such as `memory`, `knowledge`, `thinking`, and `interfaces` are direct constructor parameters on `Agent`, not nested inside `AgentConfig`.

## Required and commonly used arguments

- `model` is required and accepts either a model instance or a string shorthand such as `"openai/gpt-4o-mini"`.
- `instructions` becomes the core system prompt for the run.
- `tools`, `toolkits`, and `skills` all contribute callable capability, but at different abstraction levels.
- `session_id` sets the default session for future runs if the caller does not override it.
- `config` controls loop settings such as retry behavior and iteration limits.

## Primary execution methods

| Method | Use when |
| --- | --- |
| `run(...)` | you want a synchronous final result |
| `arun(...)` | you are already in async code |
| `run_stream(...)` | you want synchronous event streaming |
| `arun_stream(...)` | you want async event streaming |

All four methods drive the same execution lifecycle. The difference is only sync vs async and final result vs event stream.

## Important derived state

- `tool_names` shows the flattened tool set after tools, toolkits, and skills are combined.
- `session_id` is generated once at construction time if you do not provide one.
- `config` remains immutable; changing settings is done by replacing it with `config.with_updates(...)`.

## Tested example

```python
from definable.agent import Agent, AgentConfig
from definable.agent.testing import MockModel
from definable.tool import tool


@tool
def lookup_docs(topic: str) -> str:
    """Return the docs section for a topic."""
    return f"docs:{topic}"


agent = Agent(
    name="docs-agent",
    model=MockModel(responses=["Use the billing guide."]),
    instructions="Answer briefly.",
    tools=[lookup_docs],
    config=AgentConfig(max_iterations=5),
)

output = agent.run("Where should I look for billing help?")

assert agent.agent_name == "docs-agent"
assert agent.tool_names == ["lookup_docs"]
assert agent.config.max_iterations == 5
assert isinstance(agent.session_id, str)
assert output.content == "Use the billing guide."
```

## When to reach for other primitives

- Use [`AgentConfig`](/reference/agents/config) when you need to tune loop behavior rather than attach new capability layers.
