`Workflow` is the deterministic orchestration container. It executes named steps and returns a `WorkflowOutput` with top-level content, success state, duration, and step-level results.

## Constructor shape

| Field | Purpose |
| --- | --- |
| `name` | human-readable workflow name |
| `description` | optional documentation for the workflow |
| `instructions` | optional instructions appended to step prompts |
| `steps` | one step, a list of steps, or a composite such as `Parallel`, `Loop`, `Condition`, or `Router` |
| `session_state` | initial shared state visible to steps |
| `debug` | enable debug logging |

## Execution model

- `Workflow` is async-first. The primary public method is `arun(...)`.
- `steps` can be simple `Step` wrappers or higher-level composites from the workflow package.
- The return value is a `WorkflowOutput`, which exposes `content`, `success`, `error`, `duration_ms`, and step lookup helpers such as `get_step_content(...)`.

## Tested example

```python
import asyncio

from definable.agent.workflow import Step, Workflow


async def research(step_input):
    return "notes"


def draft(step_input):
    return f"draft from {step_input.get_last_step_content()}"


async def main() -> None:
    workflow = Workflow(
        name="docs-workflow",
        steps=[
            Step(name="research", executor=research),
            Step(name="draft", executor=draft),
        ],
    )
    output = await workflow.arun("Write docs.")

    assert output.success is True
    assert output.content == "draft from notes"
    assert output.get_step_content("research") == "notes"


asyncio.run(main())
```

## When to use Workflow instead of Team

Use a workflow when the execution graph should be explicit and reproducible. Use a team when the leader should decide delegation at runtime.
