Every provider response can attach a `Metrics` object, and agent runs can aggregate those numbers with `UsageTracker`. The two surfaces solve different problems: `Metrics` is per call, `UsageTracker` is per session.

## Tested aggregation

```python
from definable.agent.usage import UsageTracker
from definable.model.metrics import Metrics

first = Metrics(input_tokens=10, output_tokens=5, total_tokens=15, cost=0.001)
second = Metrics(input_tokens=7, output_tokens=5, total_tokens=12, cost=0.0005)

combined = first + second
tracker = UsageTracker()
snapshot = tracker.record_run(combined, model_id="gpt-4o-mini")

assert combined.to_dict() == {
    "input_tokens": 17,
    "output_tokens": 10,
    "total_tokens": 27,
    "cost": 0.0015,
}
assert snapshot.to_dict()["model_id"] == "gpt-4o-mini"
assert tracker.session_total.total_tokens == 27
assert round(tracker.session_total.estimated_cost, 6) == 0.0015
```

## What each layer gives you

- `Metrics`: token counts, duration, time-to-first-token, cache usage, audio usage, and cost.
- `UsageTracker`: session totals, per-run snapshots, and simple reporting helpers.

## Notes

- Cost is only as good as the pricing data or provider metrics available for the active model.
- `Metrics.to_dict()` intentionally drops zero-value and `None` fields to keep logs compact.
