Model strings are the lightest-weight way to choose a provider. They are ideal when the model choice should come from config or environment rather than from handwritten imports.

## Tested resolution

```python
from definable.model import resolve_model_string

openai = resolve_model_string("gpt-4o-mini")
deepseek = resolve_model_string("deepseek/deepseek-chat")

assert type(openai).__name__ == "OpenAIChat"
assert openai.id == "gpt-4o-mini"
assert type(deepseek).__name__ == "DeepSeekChat"
assert deepseek.provider == "DeepSeek"

try:
    resolve_model_string("unknown/model")
except ValueError as exc:
    assert "Unknown model provider" in str(exc)
else:
    raise AssertionError("Unknown providers must raise ValueError")
```

## How the shorthand works

<ModelsNote />

- `"provider/model-id"` resolves to the corresponding provider adapter.
- A bare model ID such as `"gpt-4o-mini"` defaults to OpenAI.
- Resolution only constructs the adapter; credentials are still read later when the provider client is created.

## Use class imports instead when

- You need provider-specific options such as `search_parameters`, `thinking_budget`, or `service_tier`.
- You want to inject custom clients, headers, or base URLs.
- You want the adapter choice to be explicit in code review rather than hidden in configuration.
