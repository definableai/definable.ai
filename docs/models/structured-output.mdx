title: Structured Output
description: Define a schema once and pass it to the model adapter as `response_format`.

---

Structured output is driven by Pydantic models. Definable converts your schema into the provider-specific format when the adapter supports native schema enforcement, and falls back to prompt-driven JSON guidance when it does not.

## Tested schema conversion

```python
from pydantic import BaseModel

from definable.model import DeepSeekChat, OpenAIChat


class ProjectSummary(BaseModel):
    title: str
    risk: str


openai = OpenAIChat(id="gpt-4o-mini", api_key="test-key")
params = openai.get_request_params(response_format=ProjectSummary)
deepseek = DeepSeekChat(id="deepseek-chat", api_key="test-key")

assert params["response_format"]["type"] == "json_schema"
assert params["response_format"]["json_schema"]["name"] == "ProjectSummary"
assert "properties" in params["response_format"]["json_schema"]["schema"]
assert deepseek.supports_native_structured_outputs is False
```

## What this means in practice

- Native providers receive a real JSON-schema payload.
- Non-native providers still accept the same `response_format` input, but the framework has to guide the model by prompt instead of by a provider-enforced schema field.
- `strict_output=True` matters most on native OpenAI-compatible adapters.

## Where to use it

- Direct model calls: pass `response_format=YourSchema`.
- Agent runs: pass `output_schema=YourSchema` to `run()` or `arun()`.
- Pipelines that feed typed data into later steps, especially evaluation, routing, and post-processing.
