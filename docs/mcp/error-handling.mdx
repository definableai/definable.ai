MCP errors are split by failure domain: connection setup, server lookup, and protocol-level failures.

## Tested failure cases

```python
import asyncio
import sys

from examples.docs.support import mock_mcp_server_path
from definable.mcp import MCPClient, MCPConfig, MCPServerConfig
from definable.mcp.client import MCPServerConnection
from definable.mcp.errors import MCPConnectionError, MCPProtocolError, MCPServerNotFoundError


async def main() -> None:
    broken = MCPServerConnection(MCPServerConfig(name="broken", command="definitely-not-a-real-command"))
    try:
        await broken.connect()
    except MCPConnectionError as exc:
        assert exc.server_name == "broken"

    config = MCPConfig(
        servers=[MCPServerConfig(name="mock", command=sys.executable, args=[str(mock_mcp_server_path())])]
    )

    async with MCPClient(config) as client:
        try:
            await client.list_tools("missing")
        except MCPServerNotFoundError as exc:
            assert exc.available_servers == ["mock"]

        try:
            await client.call_tool("mock", "missing")
        except MCPProtocolError as exc:
            assert exc.server_name == "mock"
            assert "Unknown tool" in str(exc)


asyncio.run(main())
```

## What is important to know

- `MCPServerConnection.connect()` raises connection errors directly.
- `MCPClient.connect()` logs per-server connection failures and continues with other configured servers.
- A server-side JSON-RPC error currently surfaces as `MCPProtocolError`, even when the semantic cause is “tool not found”.

## Error classes you will see most often

- `MCPConnectionError`: process launch, network, or transport setup failure
- `MCPServerNotFoundError`: you asked for a server name that is not configured
- `MCPProtocolError`: invalid or error JSON-RPC response from the server
