Resources are the read-only side of MCP. They are appropriate for files, config, or other structured data that should be fetched but not mutated through the tool surface.

## Tested resource lookup

```python
import asyncio
import sys

from examples.docs.support import mock_mcp_server_path
from definable.mcp import MCPClient, MCPConfig, MCPResourceProvider, MCPServerConfig


config = MCPConfig(
    servers=[MCPServerConfig(name="mock", command=sys.executable, args=[str(mock_mcp_server_path())])]
)


async def main() -> None:
    async with MCPClient(config) as client:
        resources = MCPResourceProvider(client)
        listed = await resources.list_resources("mock")
        text = await resources.read_text("mock", "docs://handbook")
        owner = await resources.find_resource("docs://handbook")
        info = await resources.get_resource_info("mock", "docs://handbook")

        assert listed["mock"][0].uri == "docs://handbook"
        assert text == "Definable documentation favors small, verified examples."
        assert owner == "mock"
        assert info.name == "handbook"


asyncio.run(main())
```

## Notes

- Use `read_text()` when you expect a plain-text resource.
- Use `read_resource()` when you need the raw typed MCP resource content objects.
- Resources are intentionally read-only. If the remote system needs mutation, that should happen through an MCP tool instead.
