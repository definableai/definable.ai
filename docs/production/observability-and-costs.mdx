Two production questions matter early:

- what is the runtime doing right now,
- how much usage is this system generating over time.

Definable separates those concerns cleanly: observability exposes the live runtime surface, while usage and metrics track run counts, latency, and token-like accounting.

## Tested example

```python
from fastapi.testclient import TestClient

from definable import Agent
from definable.agent.middleware import MetricsMiddleware
from definable.agent.runtime import AgentServer
from definable.agent.testing import MockModel

agent = Agent(model=MockModel(responses=["hello"]), observability=True, usage=True)
metrics_middleware = MetricsMiddleware()
agent.use(metrics_middleware)

output = agent.run("Hi")
client = TestClient(AgentServer(agent).create_app())

assert output.content == "hello"
assert agent.usage_tracker.run_count == 1
assert metrics_middleware.run_count == 1
assert client.get("/obs/api/health").status_code == 200
```

## Rule of thumb

- use observability for live inspection,
- use usage tracking and middleware metrics for aggregation,
- treat mock-provider token counts as local diagnostics, not real billing numbers.
