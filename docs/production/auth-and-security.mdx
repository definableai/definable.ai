title: Auth and Security
description: Lock down the runtime edge and restrict dangerous tool behavior before production traffic arrives.

---

Auth and security solve different problems:

- auth decides who may call the runtime,
- security decides what the agent and its tools may do after a call is accepted.

## Production priorities

- protect `/run` with a runtime auth provider,
- define an allowlist-style tool policy for sensitive tools,
- enable prompt-injection and SSRF defenses where external content is involved.

## Tested example

```python
from fastapi.testclient import TestClient

from definable.agent import Agent
from definable.agent.auth import APIKeyAuth
from definable.agent.runtime import AgentServer
from definable.agent.security import SecurityConfig, ToolPolicy
from definable.agent.testing import MockModel
from definable.tool import tool


@tool
def search_web(query: str) -> str:
    """Search the web for a query."""
    return f"Results for {query}"


agent = Agent(
    model=MockModel(responses=["ok"]),
    tools=[search_web],
    security=SecurityConfig(tool_policy=ToolPolicy(mode="allowlist", allowed_tools={"search_web"})),
)
agent.auth = APIKeyAuth(keys={"secret"})

client = TestClient(AgentServer(agent).create_app())

assert client.post("/run", json={"input": "ping"}).status_code == 401
assert client.post("/run", headers={"X-API-Key": "secret"}, json={"input": "ping"}).status_code == 200
assert agent.security.tool_policy.is_allowed("search_web") is True
assert agent.security.tool_policy.is_allowed("delete_file") is False
```

## Rule of thumb

Runtime auth is the first boundary. Tool policy is the second boundary. Use both.
