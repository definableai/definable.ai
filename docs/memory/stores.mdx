The store decides where memory entries live. The `Memory` manager stays the same whether you want ephemeral history, a local SQLite file, or JSONL files on disk.

## Built-in stores

| Store | Best for | Persistence |
| --- | --- | --- |
| `InMemoryStore` | tests and ephemeral runs | process memory only |
| `SQLiteStore` | local development and single-process apps | SQLite database |
| `FileStore` | inspectable flat-file storage | JSONL files per session and user |

## Tested example

```python
import asyncio
from pathlib import Path
from tempfile import TemporaryDirectory

from definable.memory import FileStore, InMemoryStore, Memory, SQLiteStore
from definable.model.message import Message


async def main() -> None:
    async with Memory(store=InMemoryStore()) as ephemeral:
        await ephemeral.add(Message(role="user", content="hello"), session_id="docs")
        assert len(await ephemeral.get_entries("docs")) == 1

    with TemporaryDirectory() as tmpdir:
        async with Memory(store=SQLiteStore(str(Path(tmpdir) / "memory.db"))) as sqlite_memory:
            await sqlite_memory.add(Message(role="user", content="sqlite"), session_id="docs")
            assert len(await sqlite_memory.get_entries("docs")) == 1

        async with Memory(store=FileStore(str(Path(tmpdir) / "files"))) as file_memory:
            await file_memory.add(Message(role="user", content="file"), session_id="docs")
            assert len(await file_memory.get_entries("docs")) == 1


asyncio.run(main())
```

## Store contract

Any custom store should implement the async `MemoryStore` protocol: `initialize`, `close`, `add`, `get_entries`, `get_entry`, `update`, `delete`, `delete_session`, and `count`.

## Guidance

- Start with `InMemoryStore` in tests.
- Use `SQLiteStore` when you want persistence without adding infrastructure.
- Use `FileStore` when human-readable storage is more useful than query performance.
