This tutorial shows the structural pattern for one agent that answers on several platforms. The goal is to keep one execution core while letting interfaces handle transport-specific behavior.

## Shape of the build

1. Create one agent.
2. Create one `InterfaceGateway` to supervise multiple transports.
3. Attach platform interfaces at construction time.
4. Decide whether sessions should be shared across interfaces.

## Tested example

```python
from definable.agent import Agent
from definable.agent.interface import DiscordInterface, SlackInterface, TelegramInterface
from definable.agent.interface.gateway import InterfaceGateway
from definable.agent.testing import MockModel

gateway = InterfaceGateway(shared_sessions=True)

telegram = TelegramInterface(bot_token="123:test")
discord = DiscordInterface(bot_token="discord-token", command_prefix="!")
slack = SlackInterface(bot_token="xoxb-test", app_token="xapp-test")

agent = Agent(
    model=MockModel(responses=["ready"]),
    gateway=gateway,
    interfaces=[telegram, discord, slack],
)

assert [interface.config.platform for interface in agent.interfaces] == ["telegram", "discord", "slack"]
assert gateway.interfaces[0].session_manager is gateway.interfaces[1].session_manager
```

## Deployment notes

- This page validates constructor and wiring shape, not a live provider session.
- Replace the mock model with a real provider before exposing the agent publicly.
- Add an identity resolver when one user should carry memory across transports.
