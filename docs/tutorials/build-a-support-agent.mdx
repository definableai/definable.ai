This tutorial is the shortest path to a practical assistant: one agent, one domain-specific tool, and a response loop that is easy to test before you connect a real provider.

## Shape of the build

1. Create one focused tool for the domain.
2. Attach it to a single `Agent`.
3. Keep the first version local and deterministic.
4. Add memory or knowledge only when you have a clear retrieval need.

## Tested example

```python
from definable.agent import Agent
from definable.agent.testing import MockModel
from definable.tool import tool


@tool
def lookup_policy(topic: str) -> str:
    """Return the support policy section for a topic."""
    return f"Policy for {topic}"


agent = Agent(
    name="support-agent",
    model=MockModel(responses=["Refunds close after 30 days."]),
    instructions="Answer support questions briefly and clearly.",
    tools=[lookup_policy],
)

output = agent.run("Summarize the refund policy.")

assert agent.tool_names == ["lookup_policy"]
assert output.content == "Refunds close after 30 days."
```

## When to expand this design

- Add [`Knowledge`](/knowledge/overview) when answers should be grounded in policy documents or handbooks.
- Add [`Memory`](/memory/overview) when the assistant should remember user-specific history across sessions.
- Add [`Guardrails`](/guardrails/overview) when answers or tools need policy enforcement.
