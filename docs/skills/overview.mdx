`definable.skill` sits above individual tools. A skill packages domain-specific instructions together with one or more tools and optional dependencies, so an agent receives both capability and behavioral guidance as a unit.

## When to use a skill

Use a skill when the capability should ship with its own operating guidance:

- domain-specific instructions should always accompany the tools
- the capability should be installable or discoverable as a reusable package
- the same bundle should plug into multiple agents with minimal wiring

If you only need grouped tools, a [`Toolkit`](/toolkits/overview) is usually enough.

## Public API

| Type | Purpose |
| --- | --- |
| `Skill` | Base skill type |
| `SkillRegistry` | Discover and load installable skills |
| `MarkdownSkill`, `SkillLoader` | Markdown-defined skill format |
| Built-ins such as `Calculator`, `WebSearch`, `DateTime`, `Shell`, `MacOS` | Reusable built-in skills |

## Tested example

```python
from definable.agent import Agent
from definable.agent.testing import MockModel
from definable.skill import Skill
from definable.tool import tool


@tool
def lookup_policy(topic: str) -> str:
    """Return the policy section for a topic."""
    return f"Policy for {topic}"


support = Skill(
    name="support_docs",
    instructions="Check policy documentation before answering.",
    tools=[lookup_policy],
)

agent = Agent(
    model=MockModel(responses=["Refunds close after 30 days."]),
    skills=[support],
)

output = agent.run("Summarize the refund policy.")

assert "lookup_policy" in agent.tool_names
assert output.content == "Refunds close after 30 days."
```
