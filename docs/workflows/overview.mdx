`Workflow` is the deterministic orchestration layer. It executes explicit steps and returns a `WorkflowOutput` containing step-level results.

## When to use a workflow

Use a workflow when:

- the execution graph should be explicit and reproducible
- the same step order should run regardless of model choice
- each stage needs step-level outputs and inspection
- some steps are agents, teams, and plain functions side by side

If the system should decide the next specialist dynamically, use a [`Team`](/teams/overview).

## Step types

| Type | Purpose |
| --- | --- |
| `Step` | wrap one agent, team, or callable |
| `Steps` | run steps sequentially |
| `Parallel` | run steps concurrently |
| `Condition` | choose a branch from a boolean predicate |
| `Loop` | repeat steps until an end condition is met |
| `Router` | choose one or more named routes dynamically |

## Tested example

```python
import asyncio

from definable.agent.workflow import Step, Workflow


async def research(step_input):
    return "Research notes"


def draft(step_input):
    return f"Draft from {step_input.get_last_step_content()}"


async def main() -> None:
    workflow = Workflow(
        name="publish",
        steps=[
            Step(name="research", executor=research),
            Step(name="draft", executor=draft),
        ],
    )
    output = await workflow.arun("Write an overview.")

    assert output.content == "Draft from Research notes"
    assert output.get_step_content("research") == "Research notes"


asyncio.run(main())
```

## Practical guidance

- Use workflows when the control flow should be explicit and reproducible.
- Prefer callables or mock-backed agents in tests.
- Add teams inside workflows when a single step still needs model-driven coordination.
