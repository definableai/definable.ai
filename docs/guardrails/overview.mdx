`definable.agent.guardrail` is the policy layer around the run loop. Guardrails can inspect user input before the model runs, inspect model output before it is returned, and inspect tool calls before a tool executes.

## Public API

| Type | Purpose |
| --- | --- |
| `Guardrails` | Container for input, output, and tool guardrails |
| `GuardrailResult` | Result object returned by every guardrail |
| `input_guardrail`, `output_guardrail`, `tool_guardrail` | Decorators for custom guardrails |
| `max_tokens`, `regex_filter`, `pii_filter`, `tool_allowlist`, `tool_blocklist` | Built-in policies |

## Checkpoints

- Input guardrails run before the model call.
- Output guardrails run after the model call.
- Tool guardrails run before each tool invocation.

## Tested example

```python
import asyncio

from definable.agent import Agent
from definable.agent.guardrail import Guardrails, max_tokens
from definable.agent.run import RunStatus
from definable.agent.testing import MockModel


async def main() -> None:
    agent = Agent(
        model=MockModel(responses=["ok"]),
        guardrails=Guardrails(
            input=[max_tokens(2)],
            on_block="return_message",
        ),
    )

    output = await agent.arun("This input should be blocked before the model runs.")

    assert output.status == RunStatus.blocked


asyncio.run(main())
```

## Guidance

- Use built-in guardrails first. They are easy to audit and compose.
- Set `on_block` deliberately. Returning a message is better for product flows; raising is better for strict service boundaries.
- Keep tool guardrails narrow and explicit. Tool policy is one of the highest-impact safety controls.
