Cost tracking has two distinct surfaces:

- `output.metrics` for one completed run
- `agent.usage_tracker` and `MetricsMiddleware` for longer-lived aggregation

## Tested agent-level tracking

```python
from definable import Agent
from definable.agent.middleware import MetricsMiddleware
from definable.agent.testing import MockModel

usage_agent = Agent(model=MockModel(responses=["hello"]), usage=True)
usage_output = usage_agent.run("Hi")

assert usage_output.content == "hello"
assert usage_agent.usage_tracker.run_count == 1
assert usage_agent.usage_tracker.session_total.runs == 1

metrics_middleware = MetricsMiddleware()
latency_agent = Agent(model=MockModel(responses=["hello"]))
latency_agent.use(metrics_middleware)
latency_agent.run("Hi")

assert metrics_middleware.run_count == 1
assert metrics_middleware.error_count == 0
assert metrics_middleware.average_latency_ms > 0
```

## When to use what

- Use `UsageTracker` when you need cumulative session totals.
- Use `MetricsMiddleware` when you want latency and failure counts across many runs.
- Use raw `Metrics` objects when you want to aggregate or serialize usage yourself.

## Notes

- Mock providers often report zero tokens and zero cost, which is expected in local tests.
- Real provider cost data depends on provider response metadata and the pricing registry used by the framework.
