Identity resolution lets one human keep the same memory and account mapping across multiple transports. Instead of treating `telegram:42` and `slack:U123` as unrelated users, the resolver maps both to a canonical identifier that the rest of the agent stack can share.

## Tested example

```python
import asyncio
from pathlib import Path
from tempfile import TemporaryDirectory

from definable.agent.interface import SQLiteIdentityResolver


async def main() -> None:
    with TemporaryDirectory() as tmp_dir:
        resolver = SQLiteIdentityResolver(db_path=str(Path(tmp_dir) / "identity.db"))
        async with resolver:
            await resolver.link("telegram", "42", "user-1", username="alice")
            await resolver.link("slack", "U123", "user-1", username="alice-work")

            assert await resolver.resolve("telegram", "42") == "user-1"

            identities = await resolver.get_identities("user-1")
            assert sorted(identity.platform for identity in identities) == ["slack", "telegram"]
            assert identities[0].canonical_user_id == "user-1"


asyncio.run(main())
```

## How to apply it

- Pass a resolver to `InterfaceGateway(identity_resolver=...)` when several interfaces should share it.
- Use the gateway when you want one place to manage linking, shared sessions, and cross-platform lifecycle.
- Turn on gateway-driven identity linking when you want the built-in `/link` flow between platforms.

## Built-in implementation

`SQLiteIdentityResolver` is the shipped persistence layer. It is async, self-initializing, and appropriate for local deployments or small shared identity graphs.
