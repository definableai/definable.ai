`CallInterface` is the voice transport for the agent layer. It mounts HTTP and WebSocket routes on the runtime, hands telephony traffic to a voice pipeline, and keeps call state inside the same agent execution model as the rest of the platform interfaces.

## When to use it

- Use `pipeline="managed"` when your telephony provider should handle STT and TTS.
- Use `pipeline="cascading"` when you want separate speech-to-text and text-to-speech providers.
- Use `pipeline="realtime"` when you want a speech-to-speech provider to own the turn loop directly.

## Tested example

```python
from examples.docs.interfaces_call_modes import main

summary = main()

assert summary["managed_mode"] == "managed"
assert summary["cascading_mode"] == "cascading"
assert summary["realtime_mode"] == "realtime"
assert "/call/incoming" in summary["router_paths"]
assert "/call/stream/{call_id}" in summary["router_paths"]
```

## What the interface provides

- Telephony provider selection through `provider="twilio"` or `provider="plivo"`.
- Runtime-mounted routes for inbound call setup, stream handling, and status callbacks.
- A consistent agent-facing interface even when the speech pipeline changes.
- Call-scoped session management with longer defaults than text interfaces.

## Operational notes

- `Twilio` supports all three pipeline modes.
- `Plivo` does not support `managed` mode. Use `cascading` or `realtime` there.
- The interface expects to run under the agent runtime because it exposes HTTP and WebSocket routes.

## Building blocks

- `STTProvider` and `TTSProvider` are required for `pipeline="cascading"`.
- `RealtimeProvider` is required for `pipeline="realtime"`.
- `welcome_message`, `voice`, `language`, and interrupt settings are shared configuration points across the modes.
