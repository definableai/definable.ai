`SlackInterface` supports both interactive chat flows and structured Slack app surfaces. It covers DMs, mentions, thread replies, slash commands, Block Kit callbacks, reaction events, and App Home hooks while keeping the transport inside the same agent runtime model as the rest of the platform interfaces.

## Tested example

```python
from definable.agent.interface import SlackInterface


async def handle_ask(command: dict) -> None:
    return None


async def handle_action(action: dict, body: dict) -> None:
    return None


socket_mode = SlackInterface(
    bot_token="xoxb-test",
    app_token="xapp-test",
    slash_commands={"/ask": "Ask the assistant"},
)
http_mode = SlackInterface(
    bot_token="xoxb-test",
    signing_secret="signing-secret",
    mode="http",
)

socket_mode.on_command("/ask", handle_ask)
socket_mode.on_action("approve_button", handle_action)

assert socket_mode._slack_config.mode == "socket"
assert http_mode._slack_config.mode == "http"
assert "/ask" in socket_mode._command_callbacks
assert "approve_button" in socket_mode._action_callbacks
```

## Choose a mode

- Use Socket Mode for local development and private networks.
- Use HTTP mode when Slack should push events into a public runtime endpoint.

## What it supports

- Direct messages and `@mention` flows.
- Thread-aware session handling.
- Slash commands via `slash_commands` and `on_command()`.
- Interactive components via `on_action()`, `on_view()`, and `on_shortcut()`.
- Custom Slack event handlers via `on_event()`.
