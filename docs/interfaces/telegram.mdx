`TelegramInterface` is the most feature-rich chat transport in the agent layer. It supports polling and webhooks, inline keyboard callbacks, reaction handling, forum-topic session isolation, access policies for DMs and groups, and automatic formatting for Telegram output.

## Tested example

```python
import asyncio

from definable.agent.interface import TelegramInterface


async def handle_button(callback_query: dict) -> str:
    return "queued"


polling = TelegramInterface(
    bot_token="123:test",
    commands={"start": "Start the bot"},
    handle_reactions=True,
)
webhook = TelegramInterface(
    bot_token="123:test",
    mode="webhook",
    webhook_url="https://example.com/webhook/telegram",
    webhook_secret="secret",
)

polling.register_callback(r"^approve:", handle_button)
pattern, handler = polling._callback_handlers[0]

assert polling.config.platform == "telegram"
assert polling.config.handle_reactions is True
assert webhook.config.mode == "webhook"
assert pattern.pattern == "^approve:"
assert asyncio.run(handler({"data": "approve:42"})) == "queued"
```

## Choose a mode

- Use polling for local development or private deployments.
- Use webhook mode when you want Telegram to push updates into your runtime directly.

## What it supports

- Command menu syncing through `commands`.
- Callback query routing through `register_callback()`.
- Group and DM policy controls.
- Optional reaction handling and forum-topic isolation.
- Markdown-to-Telegram formatting and response chunking.
