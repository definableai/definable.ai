Every interface message is routed through a session. Sessions keep the stable key for a conversation, the rolling history passed back into the agent, mutable session state, and the last run output for follow-up turns.

## Tested example

```python
from definable.agent.interface import SessionManager
from definable.model.message import Message

sessions = SessionManager(session_ttl_seconds=60)

first = sessions.get_or_create("telegram", "u-1", "chat-1")
second = sessions.get_or_create("telegram", "u-1", "chat-1")

assert first.session_id == second.session_id

first.messages = [
    Message(role="user", content="hello"),
    Message(role="assistant", content="hi"),
    Message(role="user", content="follow up"),
]
first.truncate_history(2)

assert len(first.messages) == 2
assert first.messages[0].role == "assistant"
assert sessions.active_session_count == 1
```

## Session key model

- Sessions are keyed by `platform`, `platform_user_id`, and `platform_chat_id`.
- A single user can therefore have different sessions in different channels or threads.
- Shared sessions only happen when you explicitly put interfaces behind a gateway with `shared_sessions=True`.

## What lives in a session

- `messages` for multi-turn context.
- `session_state` for mutable workflow state.
- `last_run_output` when you need access to the previous execution result.
- timestamps for creation and last activity.
